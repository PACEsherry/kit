# Kit 使用指南：代码文档生成

> 本文档面向需要使用kit的开发者，聚焦于"如何用 kit 生成 markdown 格式的代码文档"。

---

## 一、kit 是什么

`kit` 是一个 **代码智能工具包**，核心能力是：

- 扫描代码仓库，提取文件结构
- 解析源码中的类、函数、方法等符号
- 生成结构化的 markdown 文档

它支持 Python、TypeScript、JavaScript 等语言，既可以本地运行，也可以连接 GitHub 远程仓库。

---

## 二、快速开始

### 1. 安装

```bash
# 进入项目目录
cd kit

# 安装依赖
uv sync

# 以开发模式安装 kit
uv pip install -e .
```

### 2. 生成文档（一行命令）

```bash
python generate_summary_output.py
```

执行后会在项目根目录生成 `summary_output.md`，包含所有源码模块的结构化摘要。

---

## 三、工作原理

`generate_summary_output.py` 的执行流程：

```
1. 扫描代码仓库 → 获取所有文件列表
2. 过滤文件 → 只保留 .py / .ts / .tsx / .js / .jsx 和配置文件
3. 解析 Python 文件 → 用 AST 提取类、方法、函数、变量
4. 生成 markdown → 按统一模板输出每个模块的摘要
```

**关键点**：这个脚本 **不调用 LLM**，完全基于 AST 解析和规则生成摘要，所以：
- 速度快（几秒内完成）
- 无额外成本
- 输出格式稳定

---

## 四、输出格式说明

生成的 markdown 遵循 `Summary_Output_Templet.md` 模板，结构如下：

```markdown
# library kit                    ← 库级摘要
## function:
## usage example:

# config kit/pyproject.toml      ← 配置文件摘要
## function:
## declaration:
## usage example:

# module kit/src/kit/cli.py      ← 模块级摘要
## function:
## usage example:

# class Repository               ← 类级摘要
## function:
## extends:
## implements:
## usage example:

# method Repository.extract_symbols(...)  ← 方法级摘要
## function:
## extends:
## implements:
## usage example:

# func get_file_tree(...)        ← 函数级摘要
## function:
## usage example:

# const MAX_FILE_SIZE            ← 常量摘要
## function:
## usage example:
```

## 五、实际使用场景

### 场景 1：快速了解陌生项目

```bash
# 克隆项目后，直接生成文档
git clone https://github.com/some-org/some-project.git
cd some-project
python /path/to/generate_summary_output.py
# 用 Markdown 阅读器打开 summary_output.md
```

### 场景 2：对比不同版本的代码结构

```bash
# 生成 v1.0 的文档
git checkout v1.0
python generate_summary_output.py
mv summary_output.md summary_v1.0.md

# 生成 v2.0 的文档
git checkout v2.0
python generate_summary_output.py
mv summary_output.md summary_v2.0.md

# 对比两个版本
diff summary_v1.0.md summary_v2.0.md
```

### 场景 3：团队知识沉淀

将生成的 markdown 文档：
- 放入项目 wiki
- 提交到 docs/ 目录
- 用作新人入职的代码导读材料

## 六、Kit 的其他能力（可选）

除了生成文档，kit 还提供：

| 功能 | 命令示例 | 说明 |
|------|---------|------|
| 提取符号 | `kit symbols /path/to/repo` | 列出所有函数、类 |
| 代码搜索 | `kit search /path/to/repo "def main"` | 正则搜索 |
| 文件树 | `kit file-tree /path/to/repo` | 目录结构 |
| PR 评审 | `kit review https://github.com/.../pull/123` | AI 代码审查 |
| 生成摘要 | `kit summarize https://github.com/.../pull/123` | PR 摘要 |

这些功能需要配置 LLM API Key（如 `ANTHROPIC_API_KEY`），文档生成不需要。

## 七、常见问题

### Q: 生成的文档太长怎么办？
A: 脚本默认扫描所有源码文件。可以修改 `SOURCE_SUFFIXES` 或在 `should_skip_path` 中添加排除规则。

### Q: 如何支持 TypeScript/JavaScript？
A: 目前 AST 解析仅支持 Python。TypeScript/JS 文件会生成模块级摘要，但不会解析内部类和函数。可以后续扩展 `parse_python_details` 为通用解析器。

### Q: 能否用 LLM 生成更智能的摘要？
A: 可以。Kit 内置 `Summarizer` 类，支持调用 OpenAI/Anthropic/Ollama 生成自然语言摘要。但会增加成本和耗时。
